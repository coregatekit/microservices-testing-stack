สภาพแวดล้อม

Docker Compose สร้างแล้ว

Phase แรก รันบนเครื่อง dev
  • สอง network: edge (gateway, Keycloak) และ backend (service, data)
  • service ไม่เปิด port ออก host เข้าได้ทาง gateway เท่านั้น
  • APISIX จะรันแบบ standalone อ่าน route จาก apisix.yaml ยังไม่ต้องมี etcd
  • รหัสผ่านอยู่ใน .env ที่ไม่ commit

k3s บน Vagrant + Ansible อยู่ในแผน

Phase ถัดไป, 1 server + 2 agents
  • role common, k3s_server, k3s_agent และ pin เวอร์ชัน k3s
  • ต้องตั้ง node-ip และ flannel-iface เพราะ NAT interface ของ Vagrant ได้ IP ซ้ำกันทุก VM
  • ปิด Traefik แล้วใช้ APISIX Ingress Controller กับ Gateway API
  • ต้องมี image registry (local หรือ GHCR) และเลือก provider กับ box ให้ตรง host

Gateway contract

เพราะจะลองเปลี่ยน gateway หลายเจ้าในอนาคต ทุกตัวต้องผ่านเงื่อนไขชุดเดียวกัน โดยเขียนเป็น contract test ที่ขยายจาก smoke-test.sh

  • 401ไม่มี token หรือ token ปลอมหรือหมดอายุ
  • 403token ถูกต้องแต่ไม่มี role customer
  • X-User-Idค่าที่ client ส่งมาต้องถูกลบ แล้วแทนด้วย claim sub จาก token ที่ตรวจแล้ว
  • tracetrace ใน Jaeger ต้องต่อเนื่องจาก gateway ถึง service
  • 429เกิน rate limit ต้องถูกปฏิเสธ

ลำดับการทำงาน

  1. ย้าย gateway เป็น APISIX

    แทน KrakenD ใน compose, ตั้ง openid-connect กับ Keycloak และเขียน contract test

  2. เพิ่ม Inventory (gRPC)

    ให้ Order เรียกต่อ แล้วดู trace ข้าม HTTP ไป gRPC ใน Jaeger

  3. เพิ่ม Catalog (GraphQL)

    route ผ่าน APISIX และลอง rate limit แบบ GraphQL

  4. Payment และ broker

    เลือก broker และ provider แล้วทำ flow รับสัญญาณชำระเงินแบบ event-driven

  5. Metrics, logs และ k6

    ต่อ Prometheus, Grafana, Loki แล้วรัน load test ดูคู่กับ resource

  6. CI และ security pipeline

    SonarQube, scanner, SBOM, signing และ DAST

  7. ย้ายขึ้น k3s

    สร้าง cluster ด้วย Vagrant และ Ansible แล้วแปลง compose เป็น Helm หรือ Kustomize

เรื่องที่ยังต้องตัดสินใจ

  • เวอร์ชัน APISIX ที่จะ pin (3.17 ขึ้นไปมี breaking change เรื่อง auth default)
  • Message broker: NATS, Redis Streams หรือ Kafka/RabbitMQ
  • Payment provider: Stripe test mode หรือ mock ที่เขียนเอง
  • CI: GitHub Actions หรือ Jenkins
  • OS ของเครื่อง host และ Vagrant provider (มีผลกับ box และชื่อ network interface)
  • Image registry สำหรับ k3s: local registry หรือ GHCR
